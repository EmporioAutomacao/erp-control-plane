⚡ Central de Ajuda — AraraSuite CP

Guia completo para gerenciar clientes, provisionamento, domínios, Cloudflare, e-mail e infraestrutura.

Fluxo de um novo cliente

1
Cliente preenche o formulário em /comecar/ ou é criado manualmente em Admin → Clientes → Adicionar.
2
Um signal post_save dispara automaticamente a task task_provisionar_cliente no Celery.
3
O motor gera .env e stack.yml em CLIENTES_BASE_PATH/{slug}/ e executa docker stack deploy. Se o cliente tiver domínio custom configurado, ele já entra no stack com as labels Traefik corretas e no ALLOWED_HOSTS.
4
Aguarda o serviço {slug}_web ficar Running (até 180s). Status muda para ativo.
5
A task task_enviar_email_boas_vindas envia o e-mail HTML com URL, usuário e senha inicial.

🔑 Acesso ao ERP do cliente

Na página do cliente, o painel "Acesso ao ERP" exibe:

  • URL — domínio custom (se configurado) ou subdomínio padrão
  • Usuário — sempre admin
  • Senha inicial — extraída do log etapa criar_superuser

A senha só aparece se o provisionamento foi concluído com sucesso. Se o cliente redefiniu a senha no ERP, a exibida aqui é a original — use Re-provisionar para ver a atual só se necessário.

🖥️ Hosts de infraestrutura

Cada cliente é alocado em um HostInfraestrutura. O campo IP é usado pelo botão ☁ Configurar Cloudflare para criar o registro DNS automaticamente.

O placement do Docker Swarm usa:

node.labels.region == {regiao}

Para ver os labels do nó:

docker node inspect {id} --format '{{.Spec.Labels}}'

⏱️ Worker Celery

Em produção o container celery processa as tasks automaticamente.

Em desenvolvimento local, suba o worker manualmente:

.\venv\Scripts\python.exe -m celery -A core worker --loglevel=info

Tarefas periódicas ficam em Agendamentos → Tarefas Periódicas. Para executá-las em dev, adicione -B ao comando acima.

Domínio custom

🌐 Como funciona o domínio custom

Todo cliente recebe por padrão um subdomínio no formato {slug}.ararasuite.com.br. O campo Domínio custom (seção Infraestrutura) permite que o cliente use também o próprio domínio — por exemplo neodistribuidora.com.br — de forma simultânea ao subdomínio padrão.

Ambos funcionam em paralelo:

  • neodistribuidora.ararasuite.com.br → ERP (rota padrão, sempre ativa)
  • neodistribuidora.com.br → mesmo ERP (rota custom adicionada)

O que o sistema configura automaticamente ao aplicar:

ComponenteO que é configurado
Django ALLOWED_HOSTS e CSRF_TRUSTED_ORIGINS incluem o domínio custom
Traefik Router adicional {slug}-erp-custom com regra Host(`dominio`) apontando para o mesmo serviço
Cloudflare Zona criada (se necessário) + registro A com proxy ativo via botão ☁ Configurar Cloudflare

O que requer ação manual do cliente (uma única vez):

O cliente precisa trocar os nameservers do domínio para os da Cloudflare no painel do registrador (Registro.br, GoDaddy, etc.). Essa etapa é obrigatória e não pode ser automatizada pois cada registrador tem painel próprio sem API padronizada. Propaga em 1–24h.

Cloudflare — configuração e automação

☁ Pré-requisitos do Cloudflare

Para o botão ☁ Configurar Cloudflare funcionar, o CP precisa de:

Variável no .env do CPDescrição
CF_API_TOKEN Token da Cloudflare com permissões:
• Zone:Zone:Read — All zones
• Zone:DNS:Edit — All zones
Criar em: Cloudflare → My Profile → API Tokens → Create Token
SERVER_IP IP público do servidor Swarm manager (ex: 104.248.189.43). Usado como fallback quando o cliente não tem um Host associado. Se o cliente tiver host, o IP vem de HostInfraestrutura.ip.

⚠️ O escopo do token deve ser "All zones" — um token restrito a ararasuite.com.br não consegue gerenciar domínios de clientes.

☁ O que o botão faz (passo a passo)

1
Chama GET /zones?name={dominio} na API da Cloudflare para verificar se a zona já existe na conta.
2
Se a zona não existe: cria via POST /zones e retorna os nameservers. O admin deve informar ao cliente para trocar no registrador. Propaga em 1–24h.
3
Verifica se já existe um registro A para o domínio apex (@).
4
Se não existe: cria A @ → IP do servidor, proxy ativo (laranja).
Se existe mas IP ou proxy estão errados: atualiza via PUT.
Se está correto: nenhuma alteração — operação idempotente.

Proxy ativo = Cloudflare cuida do HTTPS automaticamente. O servidor recebe tráfego HTTP na porta 80.

☁ Fluxo completo de ativação

1
Preencha o campo Domínio custom (ex: neodistribuidora.com.br) e salve.
2
Clique em ⚙ Aplicar Configurações — Django e Traefik passam a aceitar o domínio.
3
Clique em ☁ Configurar Cloudflare — zona e registro A criados automaticamente.
4
Se a zona foi criada agora, informe ao cliente para trocar os nameservers no registrador para os exibidos na mensagem.
5
Após a propagação do DNS (1–24h), o ERP responde em https://neodistribuidora.com.br com HTTPS automático.

☁ Casos especiais

SituaçãoComportamento
Zona já existe e A já aponta para o IP correto Nenhuma alteração. Mensagem: "registro atualizado" (idempotente)
Zona existe mas em conta diferente Cloudflare retorna erro "already exists" → mensagem de aviso. O domínio precisa ser transferido para esta conta Cloudflare.
CF_API_TOKEN ausente Mensagem de erro. Traefik e Django já foram aplicados normalmente pelo "Aplicar Configurações".
Cliente sem host associado e sem SERVER_IP Aviso: "IP do servidor não encontrado". Associe um host ao cliente ou configure SERVER_IP no .env do CP.
Domínio custom removido (campo limpo) "Aplicar Configurações" retira o domínio do ALLOWED_HOSTS e não adiciona as labels Traefik. O registro DNS na Cloudflare não é removido automaticamente — faça isso manualmente se necessário.

Infraestrutura e configurações

🔄 Recriar cliente do zero

  • Clique em Destruir — remove stack, volumes e todos os dados.
  • Crie um novo cliente com o mesmo slug (ou diferente).
  • O provisionamento dispara automaticamente.

Se quiser manter o banco, use Re-provisionar — nunca Destruir.

Resumo:

  • Aplicar Configurações → não toca no banco seguro
  • Re-provisionar → preserva banco seguro c/ backup
  • Destruir → apaga banco irreversível

✉️ Configuração de e-mail

Acesse Configurações → E-Mail para configurar o servidor SMTP.

  • Usar TLS — padrão para porta 587
  • Verificar SSL — desmarque se o certificado não corresponder ao hostname (ex: hospedagem compartilhada)
  • Botão "Enviar e-mail de teste" — envia imediatamente (síncrono) para o e-mail remetente

⚠️ Configuração do .env NÃO é usada. Apenas o registro do banco vale.

⏱️ Worker Celery

Em produção o container celery processa as tasks automaticamente.

Em desenvolvimento local:

.\venv\Scripts\python.exe -m celery -A core worker --loglevel=info

Após mudanças no código, reinicie o worker:

docker compose -f docker-compose.dev.yml restart celery

Em produção, atualize o stack com docker stack deploy apontando para a nova imagem.

💡 Dica: O subdomínio padrão ({slug}.ararasuite.com.br) sempre continua funcionando mesmo após ativar o domínio custom. Use-o como acesso de emergência caso o DNS do domínio custom tenha algum problema.
